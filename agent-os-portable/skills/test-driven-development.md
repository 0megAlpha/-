# Test-driven development skill
1. Reproduce the requested behavior or defect with a failing test.
2. State the smallest acceptance criteria and add regression coverage before changing implementation.
3. Implement the minimum change that makes the test pass.
4. Run the focused test, then the complete test suite and static checks.
5. Inspect the diff for unrelated edits, secrets, generated artifacts and accidental API changes.
6. Record commands, results and remaining limitations; never claim an unrun test passed.
